# Contributing

- Use small, reviewable changes on feature branches.
- Commit messages: imperative mood, e.g. `feat: add ...`, `fix: ...`, `docs: ...`.
- Tests required before publishing; run `pytest` locally.
- Documentation expectations: update docs/ when behavior changes.
- Pull requests: describe scope, tests, and any migration notes.
- No unrelated files in commits; stage files explicitly.
- No secrets, raw transcripts, or local DB artifacts.
